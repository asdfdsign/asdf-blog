# 차단 규칙 목록

클로드 코드가 **어떤 모드에서도 실행하지 못하는 것**의 목록. 두 파일에 나뉘어 있고, 이 문서는 그 둘을 한눈에 보기 위한 것이다.

| 범위 | 파일 | 적용 | git |
| --- | --- | --- | --- |
| **공통** | `C:\Users\user\.claude\settings.json` | 내 PC의 모든 프로젝트 | 안 올라감 |
| **프로젝트** | `D:\Claude_Local\asdf-blog\.claude\settings.json` | 이 블로그만 | 올라감 (저장소를 따라다님) |

규칙 한 줄 읽는 법 — `Bash(rm -rf*)` 는 "`rm -rf` 로 **시작하는** 셸 명령", `Write(dist/**)` 는 "`dist/` **아래 어디든** 파일 만들기", `*` 는 "뒤에 뭐가 와도". 도구 이름은 `Bash`(명령 실행) / `Edit`(기존 파일 고치기) / `Write`(파일 새로 쓰기·덮어쓰기) 세 가지만 쓴다.

기억할 것 셋:
- **deny 는 항상 이긴다.** 어느 파일에 있든, 어떤 모드든, allow 가 있어도 막힌다. 예외를 둘 수 없으니 예외가 필요하면 범위를 좁혀 쓴다 (G-6 참고).
- **모양만 본다.** `rm -rf /tmp/없는폴더` 도 막힌다. 대상이 안전한지 판단하지 않는다.
- **저장하면 바로 적용된다.** 세션을 다시 켤 필요 없다.

## 공통 — 어느 프로젝트든 같은 내 원칙 (40개)

### G-1. 폴더째 삭제 — 4개

| # | 규칙 | 뜻 |
| --- | --- | --- |
| 1 | `Bash(rm -rf*)` | 확인 없이(`f`) 폴더 안까지(`r`) 지우기 |
| 2 | `Bash(rm -fr*)` | 같은 명령, 옵션 순서만 다름 |
| 3 | `Bash(rm -r -f*)` | 같은 명령, 옵션을 띄어 쓴 것 |
| 4 | `Bash(rm -f -r*)` | 같은 명령, 옵션을 띄어 쓴 것 |

휴지통을 거치지 않아 되돌릴 수 없다. 한 파일만 지우는 `rm 파일명` 은 막지 않는다.

### G-2. git 기록 덮어쓰기 — 6개

| # | 규칙 | 뜻 |
| --- | --- | --- |
| 5 | `Bash(git push --force*)` | GitHub 의 커밋을 내 것으로 갈아엎기 |
| 6 | `Bash(git push -f *)` | 같은 명령의 짧은 표기 |
| 7 | `Bash(git push --force-with-lease*)` | "안전한 force push" 라 불리지만 기록을 다시 쓰는 건 같음 |
| 8 | `Bash(git reset --hard*)` | 커밋 안 한 변경을 전부 버리기 |
| 9 | `Bash(git filter-branch*)` | 과거 커밋 전체를 고쳐 쓰기 |
| 10 | `Bash(git push --mirror*)` | 원격을 내 로컬과 똑같이 만들기 (원격에만 있는 브랜치 삭제) |

git 의 가치는 "되돌릴 수 있다" 인데 이것들은 그 기록 자체를 지운다. 되돌려야 하면 `git revert`(기록을 남기며 되돌림), `git stash`(치워 두기), `git checkout -- 파일`(파일 하나 되돌리기) 를 쓴다.

### G-3. 관리자 권한 — 1개

| # | 규칙 | 뜻 |
| --- | --- | --- |
| 11 | `Bash(sudo*)` | 관리자 권한으로 실행 |

이게 되면 나머지 규칙을 전부 우회할 수 있다. Windows 에선 거의 안 나오지만 맥·리눅스·클라우드에서 같은 규칙이 필요하다.

### G-4. 파일 권한 활짝 열기 — 3개

| # | 규칙 | 뜻 |
| --- | --- | --- |
| 12 | `Bash(chmod 777*)` | 누구나 읽고 쓰고 실행하게 |
| 13 | `Bash(chmod -R 777*)` | 폴더 안까지 전부 |
| 14 | `Bash(chmod a+rwx*)` | 같은 뜻의 다른 표기 |

권한 문제를 "문 다 열기" 로 대충 푸는 명령. 문제를 푸는 게 아니라 없애는 것.

### G-5. 인터넷에서 받아서 바로 실행 — 8개

| # | 규칙 | 뜻 |
| --- | --- | --- |
| 15 | `Bash(curl * \| sh*)` | 받아서(`curl`) 바로 실행(`sh`) |
| 16 | `Bash(curl * \| bash*)` | 위와 같음, 실행기가 `bash` |
| 17 | `Bash(curl * \| zsh*)` | 위와 같음, 실행기가 `zsh` |
| 18 | `Bash(wget * \| sh*)` | 받는 도구가 `wget` |
| 19 | `Bash(wget * \| bash*)` | |
| 20 | `Bash(wget * \| zsh*)` | |
| 21 | `Bash(iwr * \| iex*)` | Windows PowerShell 판 (`iwr` 받기, `iex` 실행) |

설치 안내에 흔히 나오는 한 줄이지만 **읽어 보지도 않고 실행** 하는 것이다. 필요하면 먼저 파일로 받아 내용을 본 뒤 실행한다.

### G-6. 옵시디언 볼트 — 18개

| # | 규칙 | 뜻 |
| --- | --- | --- |
| 23–24 | `Edit/Write(D:/Documents/Obsidian Vault/*.md)` | 볼트 루트의 노트 (`홈.md`, `볼트 규칙.md` 등) |
| 25–26 | `Edit/Write(…/000_인박스/**)` | |
| 27–28 | `Edit/Write(…/100_개념/**)` | |
| 29–30 | `Edit/Write(…/200_문헌/**)` | |
| 31–32 | `Edit/Write(…/300_지도/**)` | |
| 33–34 | `Edit/Write(…/900_템플릿/**)` | |
| 35–36 | `Edit/Write(…/_첨부/**)` | |
| 37–38 | `Edit/Write(…/스크랩/**)` | |
| 39–40 | `Edit/Write(…/.obsidian/**)` | 옵시디언 자체 설정 |

볼트는 프로젝트가 아니라 **개인 노트** 라 클로드가 고칠 이유가 없다. 단 **`블로그/` 폴더만 뺐다** — 가져온 글의 `생성: false → true` 플래그를 바꾸기 위해서다. deny 에 예외를 둘 수 없어서 폴더를 하나씩 나열하는 방식이 됐다. **볼트에 최상위 폴더를 새로 만들면 여기에 두 줄을 추가해야 보호된다.**

같은 파일의 `sandbox.filesystem.allowWrite` 에 `D:/Documents/Obsidian Vault/블로그` 가 있다. 이건 차단이 아니라 **허용** — 프로젝트 밖 쓰기를 막는 샌드박스에 이 폴더만 열어 둔 것. 플래그 변경 절차는 `CLAUDE.md` 「옵시디언에서 가져오기」 참고.

## 넣고 빼는 법

**빼기** — 해당 파일에서 그 줄을 지우고 저장. 끝.

**넣기** — `"permissions"` → `"deny"` 배열에 한 줄 추가. 쉼표 주의 (마지막 줄 뒤에는 쉼표 없음).

```json
"Bash(명령 앞부분*)"      셸 명령
"Edit(경로/**)"           그 아래 파일 고치기
"Write(경로/**)"          그 아래 파일 만들기
```

**어디에 넣나** — "다음 프로젝트를 만들 때 복사하고 싶어질 규칙이면 공통, 이 프로젝트라서 생긴 규칙이면 프로젝트."

**넣은 뒤 확인** — 실패해도 안전한 명령으로 걸리는지 본다. 없는 폴더에 `rm -rf`, 로컬=원격일 때 `git push --force`, `--dry-run` 붙인 `npm install`. 진짜 파일·진짜 폴더로 시험하지 않는다.

**이 문서 갱신** — 규칙을 넣고 빼면 여기도 같이 고친다. 이 문서와 두 설정 파일이 어긋나면 이 문서가 틀린 것이다.
