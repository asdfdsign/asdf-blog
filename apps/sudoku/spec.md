## 2. 게임 범위 — "미니"의 정의

### 판 크기

| 크기 | 박스 | 1차 | 근거 |
| --- | --- | --- | --- |
| 4×4 | 2×2 | **넣는다** | 입문용. 한 판 1분 안팎 |
| 6×6 | 2×3 (세로 2, 가로 3) | **넣는다** | 기본값. 미니의 상한 |
| 9×9 | 3×3 | **넣지 않는다** | 아래 |

9×9 를 빼는 이유는 성능이 아니라 **화면**이다. 이 앱은 폭 360px iframe 안에서도 보드 전체가 보여야 하고 터치 타겟은 44px 이상이어야 한다. 6×6 은 `(360 − 16×2) / 6 ≈ 54px` 로 여유가 있지만 9×9 는 `≈ 36px` 로 44px 을 못 넘긴다. 9×9 는 숫자 패드도 두 줄이 되고 메모(연필) 없이는 풀기 어려워 1차 범위 밖 기능을 줄줄이 끌고 온다. 다만 `sudoku.js` 는 `size` 를 인자로 받고 박스 크기를 표에서 찾게 만들어 두어(`boxDims`) 2차에서 9×9 를 추가할 때 생성·검증 코드는 손대지 않아도 되게 한다.

### 난이도 = 빈칸 수

"목표 빈칸 수"다. 유일해를 유지하며 뺄 수 있는 만큼만 빼므로 실제 빈칸이 목표에 못 미칠 수 있다(3절). 그때는 그대로 쓴다.

| 크기 | 쉬움 `easy` | 보통 `normal` | 어려움 `hard` |
| --- | --- | --- | --- |
| 4×4 (16칸) | 6 (힌트 10) | 8 (힌트 8) | 10 (힌트 6) |
| 6×6 (36칸) | 16 (힌트 20) | 20 (힌트 16) | 24 (힌트 12) |

기본값: **6×6 · 보통**.

### 기능 — 1차에 넣는 것 / 빼는 것

| 기능 | 1차 | 이유 |
| --- | --- | --- |
| 지우기 | 넣는다 | 없으면 오타를 못 고친다 |
| 힌트 (선택 칸에 정답 채움) | 넣는다 | 막혔을 때 탈출구. 사용 횟수를 세어 완성 화면에 보여준다 |
| 충돌 즉시 표시 | 넣는다 | 4절 |
| 타이머 | 넣는다 | 완성 화면에 기록 한 줄. 일시정지 화면은 없다 |
| 숫자 패드의 "다 쓴 숫자" 흐리게 | 넣는다 | 구현이 작고(숫자별 개수 세기) 미니 판에서 체감이 크다 |
| 메모 (연필 표시) | **뺀다** | 4×4·6×6 은 후보가 적어 머리로 충분하다. 입력 모드가 둘이 되면 패드·키보드·저장 스키마가 모두 복잡해진다 |
| 실행취소 | **뺀다** | 지우기로 대신한다 |
| 자동 후보 표시·전략 힌트 | **뺀다** | 메모가 전제다 |

## 3. 퍼즐 생성 방식

매번 새 판이어야 한다. 완성판을 만들고 → 유일해를 유지하며 칸을 지운다. 전부 **메인 스레드에서 동기**로 돌리며 Web Worker 는 쓰지 않는다(6×6 이 상한이라 필요 없음).

### 자료 구조

- 보드는 **길이 N² 의 평탄한 배열**. `index = row * N + col`, 값 `0` 은 빈칸, `1..N` 이 숫자.
- 저장·전송할 때는 `"0"`~`"9"` 문자열로 인코딩한다(`encode` / `decode`).
- 박스 크기: `boxDims(4) → {rows: 2, cols: 2}`, `boxDims(6) → {rows: 2, cols: 3}`, `boxDims(9) → {rows: 3, cols: 3}`. 박스 번호 `Math.floor(r / rows) * (N / cols) + Math.floor(c / cols)`.

### 1) 완성판 생성 `generateSolution(size, rng)`

- 행 우선으로 빈칸을 순회하며, 각 칸의 후보(행·열·박스에 없는 숫자)를 **무작위로 섞어** 하나씩 넣고 백트래킹.
- 4×4·6×6 은 1ms 미만. 실패는 없다(빈 판은 항상 해가 있다).

### 2) 칸 제거 (유일해 유지)

1. 완성판을 복사해 `puzzle` 로 둔다. 인덱스 `0..N²−1` 을 섞는다.
2. 섞은 순서대로 칸 하나를 `0` 으로 바꾸고 `countSolutions(puzzle, size, 2)` 를 부른다.
3. 결과가 `1` 이면 확정, 아니면 되돌린다.
4. 빈칸 수가 목표에 도달하면 멈춘다. 모든 칸을 다 돌아도 목표에 못 미치면 **그 상태로 반환**한다(반환값의 `blanks` 가 실제 빈칸 수).

대칭 제거는 하지 않는다(미니 판에서 도달 가능한 빈칸 수를 깎아먹고, 보기에도 차이가 없다).

### 3) 유일해 검증 `countSolutions(grid, size, limit)`

- 백트래킹 + **MRV**(후보가 가장 적은 빈칸부터). 행·열·박스 사용 여부는 비트마스크(`1 << v`)로 들고 다닌다.
- 해를 `limit`(기본 2)개 찾는 즉시 중단한다. 반환값은 `0 | 1 | 2`.
- **노드 상한** `maxNodes = 20000`. 넘기면 즉시 `2` 를 돌려준다 = "유일하다고 확신 못 함" 으로 취급해 그 칸은 되돌린다. 유일해 보장은 유지되면서(보수적) 최악의 경우에도 시간이 폭주하지 않는다.

### 성능 예산과 대안

- 예산: `generate()` 한 번에 **100ms 안** (메인 스레드). 6×6 어려움은 solver 를 최대 36번 부르고 각 호출은 1ms 안팎이라 실측 5~30ms 를 예상한다. 4×4 는 1ms 급.
- `test.html` 에서 크기×난이도별 20회 생성의 평균·최대 ms 를 표로 찍는다. 기준: **최대 100ms 미만**.
- 대안(넘길 때): 노드 상한이 1차 방어선이다. 그래도 `generate()` 자체가 `performance.now()` 로 잰 200ms 를 넘기면 그 판을 버리고 새 시드로 1회 재시도, 재시도도 넘기면 목표 빈칸을 한 단계 낮춰(`hard → normal`) 생성한다. 이 경로는 6×6 에선 사실상 타지 않지만 코드로 남겨 둔다.

### 난수

- `createRng(seed)` — mulberry32. `seed` 를 주면 같은 판이 재현된다(테스트·디버그용). 앱에서는 `Date.now() ^ (Math.random() * 2**31)` 로 시드를 만들고, 생성 결과와 함께 시드를 상태에 저장한다(버그 신고 재현용).

## 4. UI 흐름

### 화면 구성 (모바일, 위에서 아래)

```
┌──────────────────────────────┐
│ ← 블로그   미니 스도쿠     ☾ │  header  (임베드 모드에선 숨김)
├──────────────────────────────┤
│ [4×4|6×6]  [쉬움|보통|어려움] │  controls
│ [ 새 게임 ]                   │
├──────────────────────────────┤
│                              │
│           보드               │  board  (정사각형, 폭 = min(100%, 440px))
│                              │
├──────────────────────────────┤
│ 03:21          힌트 1 · 남은 7│  status  (aria-live)
├──────────────────────────────┤
│ [1][2][3][4][5][6]           │  numpad  (숫자 1..N, 44×44 이상)
│ [ 지우기 ]   [ 힌트 ]         │
└──────────────────────────────┘
```

- **header**: 왼쪽 `← 블로그` 링크(`../../`), 가운데 제목, 오른쪽 테마 토글. 
- **controls**: 크기·난이도는 세그먼트 버튼(`role="radiogroup"`). 값을 바꾸면 **확인 없이 즉시 새 게임**을 시작한다. 미니 판은 짧아 잃을 게 적고, iframe 안에서 `confirm()` 대화상자는 흉하다. `새 게임` 도 즉시.
- **board**: CSS Grid `repeat(N, 1fr)`, `aspect-ratio: 1`. 칸 경계 1px `--border`, 박스 경계와 바깥 테두리 2px `--text`. 숫자는 `tabular-nums`, 4×4 는 `1.75rem`, 6×6 은 `1.5rem`.
- **status**: 왼쪽 타이머 `mm:ss`, 오른쪽 `힌트 n · 남은 m`. 완성 시 이 줄이 축하 문구로 바뀐다.
- **numpad**: 숫자 버튼 1..N 한 줄(6×6 도 360px 에서 한 줄에 들어간다: 6 × 48 + 간격), 아래 줄에 `지우기`·`힌트`. 보드에 그 숫자가 N 개 놓이면(충돌 없이) 버튼을 `--text-muted` 로 흐리게 + `aria-disabled="true"`(눌러도 무시).

### 레이아웃 차이

| 폭 | 배치 |
| --- | --- |
| < 640px | 위 그림 그대로 한 열. 좌우 여백 16px |
| ≥ 640px | controls 가 한 줄(크기·난이도·새 게임). 나머지는 한 열 유지, 전체 `max-width: 480px` 가운데 정렬 |
| ≥ 960px | 바꾸지 않는다. 2열(보드 왼쪽·패드 오른쪽)은 하지 않는다 — 데스크톱은 키보드 입력이 주가 되어 패드 위치가 덜 중요하고, 한 열이 iframe 과 코드 경로를 하나로 유지한다 |

### 임베드 모드 (iframe)

- `window.self !== window.top` 이면 `<html data-embed>` 를 붙인다(head 의 `theme.js` 에서 함께 처리).
- 임베드에서: header 숨김, 좌우 여백 8px, **순서를 board → status → numpad → controls 로** 바꿔(`order`) 보드가 항상 맨 위에 오게 한다. 보드 한 변은 `min(100%, 440px, 100dvh − 120px)` 로 잡아 iframe 높이가 낮아도 보드 + 숫자 한 줄은 스크롤 없이 보인다.
- 블로그 카드에 넣을 때 권장 iframe: `width` 카드 폭(≥ 320px), `height: 480px`, `loading="lazy"`, `title="미니 스도쿠 미리보기"`.

### 입력

| 동작 | 터치/마우스 | 키보드 |
| --- | --- | --- |
| 칸 선택 | 칸 탭 | Tab 으로 보드 진입 → 화살표(끝에서 반대편으로 감김) |
| 숫자 입력 | 숫자 패드 탭 | `1`~`N` (N 초과 숫자는 무시) |
| 지우기 | 이미 든 숫자를 패드에서 다시 탭(토글) 또는 `지우기` | `Backspace` `Delete` `0` |
| 힌트 | `힌트` 버튼 | 없음 (버튼을 Tab 으로 찾는다) |
| 새 게임 | `새 게임` 버튼 | 없음 |

- 선택은 **roving tabindex**: 선택 칸만 `tabindex="0"`, 나머지 `-1`. 보드는 Tab 한 번으로 들어오고 나간다.
- 주어진 칸(given)과 힌트로 채운 칸은 선택·이동은 되지만 입력·지우기를 무시한다.
- 선택 칸이 없을 때 숫자를 누르면 무시. 힌트는 선택 칸이 없거나 이미 찬 칸이면 **행 우선 첫 빈칸**을 골라 선택한 뒤 채운다.

### 칸 상태와 표시

색은 전부 CSS 변수. 포인트 컬러(`--accent`)는 "선택됨 / 관련 있음 / 문제 있음" 에만 쓴다.

| 상태 | 배경 | 글자 | 색 아닌 단서 |
| --- | --- | --- | --- |
| 기본 | `--bg` | `--text` 400 | — |
| 주어진 칸 | `--bg` | `--text` **700** | 굵기, `aria-readonly` |
| 힌트로 채운 칸 | `--bg` | `--text-muted` 400 | `aria-readonly`, 라벨에 "힌트" |
| 같은 행·열·박스 (peer) | `--bg-elevated` | 그대로 | — (보조 표시라 단서 불필요) |
| 선택 칸과 같은 숫자 | 그대로 | `--accent` | — |
| 선택 칸 | `--accent-soft` | 그대로 | `box-shadow: inset 0 0 0 2px var(--accent)`, `aria-selected="true"` |
| **충돌** | `--accent-soft` | `--accent` | `text-decoration: underline wavy`, `aria-invalid="true"`, 라벨에 "충돌" |

- 충돌 = 같은 행·열·박스에 같은 숫자가 둘 이상. **모든 입력 직후** `findConflicts` 로 다시 계산하며, 주어진 칸도 충돌에 포함해 표시한다(사용자가 넣은 숫자가 given 과 겹치면 둘 다 표시).
- 정답과 다르지만 충돌은 아닌 숫자는 표시하지 않는다(그건 풀이의 일부다).

### 완성

- 조건: 모든 칸이 차 있고 충돌이 없다(`isComplete`). 유일해이므로 정답과 같다는 뜻.
- 즉시: 타이머 정지, 입력·힌트·패드 비활성, 보드에 `is-complete` 클래스(바깥 테두리 `--accent`, 칸이 왼쪽 위부터 40ms 간격으로 짧게 떠오르는 stagger, 총 0.6초 안), status 가 `완성! 03:21 · 힌트 1회` 로 바뀌며 `aria-live="polite"` 로 읽힌다, 포커스를 `새 게임` 버튼으로 옮긴다.
- 저장된 진행 상태는 `complete: true` 로 갱신하고, 다음 로드 때 완성 판은 이어하지 않고 새 게임을 만든다.
- `prefers-reduced-motion: reduce` 면 stagger 와 모든 transition 을 끈다.

### 타이머

- `새 게임` 시점부터 초 단위. `document.hidden` 이면 멈추고 다시 보이면 이어간다. 저장 상태에 `elapsed`(초) 를 넣어 새로고침해도 이어진다.

### 테마

- head 에서 `theme.js` 를 **동기** 로드해 첫 페인트 전에 `data-theme` 를 붙인다(블로그와 같은 `localStorage` 키 `theme`, 없으면 `prefers-color-scheme`).
- 앱 자체 토글을 **둔다**: 앱을 새 탭에서 열었을 때 바꿀 방법이 있어야 한다. 임베드 모드에선 숨긴다(부모 페이지가 주인).
- `storage` 이벤트로 `theme` 키가 바뀌면 즉시 따라간다 → 블로그에서 토글하면 같은 출처의 iframe 도 같이 바뀐다.

## 5. 상태 저장

`localStorage`, 접두사 `sudoku:`. 블로그의 `theme` 키와 충돌하지 않는다.

| 키 | 내용 | 갱신 시점 |
| --- | --- | --- |
| `sudoku:prefs` | `{ "v": 1, "size": 6, "difficulty": "normal" }` | 크기·난이도 바꿀 때 |
| `sudoku:game` | 아래 | 칸 입력·지우기·힌트 직후, `visibilitychange`(hidden)·`pagehide` 때(`elapsed` 반영), 완성 때 |

```json
{
  "v": 1,
  "size": 6,
  "difficulty": "normal",
  "seed": 1726900000,
  "puzzle":   "030000600...",   // 길이 N², 0 = 빈칸 (주어진 칸 판별용)
  "solution": "132456645...",
  "board":    "132000600...",   // 현재 상태 (given 포함)
  "hinted":   [7, 20],          // 힌트로 채운 인덱스
  "hints": 2,
  "elapsed": 201,
  "complete": false
}
```

- 로드 순서: `sudoku:game` 이 있고 `v === 1` 이고 `complete === false` 이고 `size` 가 지원 목록에 있으면 **이어한다**. 아니면 `sudoku:prefs`(없으면 6×6·보통)로 새 게임.
- 파싱 실패·스키마 불일치는 조용히 버리고 새 게임. 콘솔 에러를 내지 않는다.
- `localStorage` 접근은 전부 `try/catch`(프라이빗 모드). 실패해도 게임은 된다(저장만 안 될 뿐).
- 타이머 틱마다 저장하지 않는다(위 갱신 시점에만).

## 6. 접근성

- 보드: `<div role="grid" aria-label="스도쿠 6×6 보드">` → 행 `<div role="row">` → 칸 `<button role="gridcell">`.
- 칸 라벨은 매 렌더에 갱신: `aria-label="2행 3열, 5"` / `"2행 3열, 빈 칸"` / `"… 주어진 숫자"` / `"… 힌트"` / 충돌이면 뒤에 `", 충돌"`.
- 선택 칸 `aria-selected="true"`, 주어진·힌트 칸 `aria-readonly="true"`, 충돌 칸 `aria-invalid="true"`.
- 포커스 링은 숨기지 않는다(`:focus-visible` 에 `--accent` 2px outline).
- status 는 `aria-live="polite"`. 완성·힌트 사용 때만 문구가 바뀌게 해서 매초 타이머로 시끄럽게 하지 않는다(타이머 숫자는 `aria-hidden` 인 별도 span).
- 숫자 패드 `aria-label="숫자 5 입력"`, 지우기·힌트·새 게임은 텍스트 버튼.
- 키보드만으로 완주 가능: Tab → 컨트롤 → 보드(화살표) → 숫자 키 → Tab → 패드/힌트/새 게임. 마우스 전용 동작 없음.
- 대비: 팔레트가 블로그와 같으므로 본문·보조·포인트 모두 4.5:1 을 이미 넘는다. 새로 생기는 조합 `--accent` 위 `--accent-soft`(선택·충돌 칸)만 Review 에서 양쪽 테마 실측한다.
- 모든 버튼 `min-width/min-height: 44px`, `touch-action: manipulation`(더블탭 확대 지연 제거; `user-scalable=no` 는 쓰지 않는다).


- 모든 경로 상대(`./style.css`, `./app.js`, `../../`).

## 8. `sudoku.js` 공개 함수

전부 `window.Sudoku` 아래. 순수 함수 — 입력을 변형하지 않고 새 배열을 돌려준다. 보드 인자는 항상 `number[]`(길이 N²).

| 함수 | 입력 | 출력 | 비고 |
| --- | --- | --- | --- |
| `SIZES` | — | `[4, 6]` | 지원 크기 상수 |
| `DIFFICULTY` | — | `{4: {easy: 6, normal: 8, hard: 10}, 6: {easy: 16, normal: 20, hard: 24}}` | 목표 빈칸 수 |
| `boxDims(size)` | `4 \| 6 \| 9` | `{rows, cols}` | 미지원 크기는 `throw` |
| `peers(size, index)` | | `number[]` | 같은 행·열·박스 인덱스(자기 자신 제외). 캐시해도 된다 |
| `createRng(seed)` | `number` | `() => number` [0,1) | mulberry32. 같은 시드 = 같은 수열 |
| `generateSolution(size, rng?)` | | `number[]` | 완성판. `rng` 생략 시 `Math.random` |
| `countSolutions(grid, size, limit = 2, maxNodes = 20000)` | | `0 \| 1 \| 2` | 상한 초과 시 `2` |
| `solve(grid, size)` | | `number[] \| null` | 첫 해. 테스트·디버그용 |
| `generate({size, difficulty, seed?})` | | `{size, difficulty, seed, puzzle, solution, blanks}` | 3절 절차 전체. `blanks` 는 실제 빈칸 수 |
| `findConflicts(board, size)` | | `number[]` | 충돌에 걸린 칸 인덱스(중복 없음, 오름차순). 빈칸(0)은 무시 |
| `isValidBoard(board, size)` | | `boolean` | 값 범위·길이 검사 (저장 복원 시) |
| `isComplete(board, size)` | | `boolean` | 빈칸 없음 && 충돌 없음 |
| `digitCounts(board, size)` | | `number[]` | 인덱스 `1..N` 에 각 숫자 개수 (패드 흐리게용) |
| `encode(board)` / `decode(str)` | | `string` / `number[]` | `"0".."9"` 문자열 ↔ 배열 |

### `test.html`

**둔다.** 블로그의 `test/markdown.test.html` 처럼 케이스 표(이름 · 기대 · 실제 · 통과 여부)와 맨 위 요약(n/m 통과, 생성 시간)을 낸다. 케이스:

1. `boxDims` 4·6·9 값, 5 는 throw
2. `generateSolution(4)`, `(6)` 각 10회: 모든 행·열·박스가 `1..N` 순열
3. `createRng(42)` 두 번 → 처음 5개 값 동일; `generate({size:6, difficulty:'normal', seed:42})` 두 번 → `puzzle` 동일
4. 크기 2 × 난이도 3 × **20회** `generate`: 각각 `countSolutions(puzzle) === 1`, `solve(puzzle)` 이 `solution` 과 같음, given 칸이 `solution` 과 일치, `blanks` 가 목표와 같음(미달이면 경고로 표시하되 실패는 아님 — 몇 회 미달인지 숫자로 남긴다)
5. 위 120회의 생성 시간 평균·최대(ms). **최대 < 100ms** 가 통과 기준
6. `findConflicts`: 충돌 없는 판 → `[]`; 행 충돌·열 충돌·박스 충돌 각 1케이스; given 이 포함된 충돌
7. `isComplete`: 완성판 true, 빈칸 하나 false, 다 찼지만 충돌 false
8. `encode/decode` 왕복, `isValidBoard` 길이·값 범위 오류
9. `digitCounts`

## 9. 검증 체크리스트 (Review 용)

로컬은 `python -m http.server 8000` 으로 띄우고 `http://localhost:8000/apps/sudoku/` 에서 본다. 코드만 읽고 넘어가지 않는다.

**생성·로직**
- [ ] `test.html` 전부 통과. 생성 시간 최대 < 100ms
- [ ] 콘솔에서 `for (let i=0;i<20;i++) Sudoku.countSolutions(Sudoku.generate({size:6,difficulty:'hard'}).puzzle, 6)` 가 전부 `1`
- [ ] 새 게임 20번 연속 눌러도 같은 판이 나오지 않고(시드가 다르고) 멈춤·에러 없음

**화면·레이아웃**
- [ ] 375px 폭에서 가로 스크롤 없음 (`document.documentElement.scrollWidth <= innerWidth`)
- [ ] 375px 에서 6×6 칸과 모든 버튼이 44×44px 이상
- [ ] 폭 360px·높이 480px iframe(`<iframe src="apps/sudoku/" width="360" height="480">` 를 임시 HTML 로) 안에서 보드 전체 + 숫자 패드 한 줄이 스크롤 없이 보이고, header 가 숨겨져 있음
- [ ] ≥ 640px 에서 controls 가 한 줄, 전체가 480px 안에 가운데 정렬

**테마·대비**
- [ ] 블로그(`/`)에서 다크로 토글 → 앱을 새 탭에서 열면 다크로 뜨고 플래시 없음(새로고침 5회)
- [ ] 앱 토글로 라이트 전환 → 블로그 탭 새로고침 시 라이트
- [ ] 라이트/다크에서 선택 칸·충돌 칸(`--accent` on `--accent-soft`), 보조 텍스트, 흐린 패드 버튼 대비 4.5:1 이상 (DevTools 색 피커로 실측)
- [ ] `[data-theme]` 밖(컴포넌트 CSS)에 하드코딩된 색상값 없음 (`grep -n "#[0-9a-fA-F]\{3,6\}" style.css` 가 변수 정의 블록에서만 걸림)

**입력·게임 흐름**
- [ ] 마우스 없이 Tab·화살표·숫자·Backspace 만으로 4×4 한 판 완주 → 완성 문구, 포커스가 새 게임으로 이동
- [ ] 같은 행/열/박스에 같은 숫자를 넣으면 두 칸 모두 즉시 충돌 표시(물결 밑줄 + 색), 하나를 지우면 즉시 해제
- [ ] given 칸에 숫자·Backspace 를 눌러도 변하지 않음. 힌트로 채운 칸도 마찬가지
- [ ] 힌트: 선택 없이 누르면 첫 빈칸이 채워지고 선택됨, 카운트 증가, 완성 문구에 횟수 표시
- [ ] 숫자를 N 개 다 놓으면 패드 버튼이 흐려지고 눌러도 무시
- [ ] 크기·난이도 변경 시 즉시 새 게임, `sudoku:prefs` 갱신

**저장·복원**
- [ ] 몇 칸 입력 → 새로고침 → 같은 판·같은 입력·타이머 이어짐
- [ ] 완성 후 새로고침 → 새 게임
- [ ] `localStorage.setItem('sudoku:game', '{broken')` 후 새로고침 → 에러 없이 새 게임
- [ ] 탭을 숨겼다 돌아오면 그 사이 시간은 타이머에 더해지지 않음

**기타**
- [ ] 콘솔 에러·경고 없음 (로드, 20판 생성, 완성, 테마 토글 전 과정)
- [ ] `prefers-reduced-motion: reduce` 에뮬레이션에서 완성 애니메이션·transition 없음
- [ ] 스크린리더 라벨: 칸에 포커스하면 "n행 m열, 값/빈 칸(, 주어진 숫자 | 힌트)(, 충돌)" 형태 (DevTools Accessibility 패널로 확인)
- [ ] 모든 경로가 상대 경로(`grep -n 'href="/\|src="/' index.html` 결과 없음)
