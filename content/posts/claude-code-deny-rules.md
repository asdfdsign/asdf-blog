앞 글에서 권한 모드를 정리하면서 "진짜 금지선은 모드가 아니라 차단 규칙에 적는다"고 했습니다. 그런데 정작 그 차단 규칙은 첫 블로그 때 뜻도 모른 채 따라 넣은 것이었습니다. 오늘은 33개를 하나하나 뜯어 보고, 어디에 둬야 하는지 다시 나눴습니다.

## 차단 규칙이란

설정 파일에 적어 두는 **"이건 절대 실행하지 마라"** 목록입니다. 영어로는 `deny`. 자동 모드든 권한 무시 모드든 이 목록에 있으면 실행되지 않습니다.

규칙은 한 줄에 하나, 모양은 이렇습니다.

```
"Bash(rm -rf*)"          rm -rf 로 시작하는 셸 명령
"Edit(dist/**)"          dist/ 아래 파일 고치기
"Write(package.json)"    package.json 파일 만들기
```

괄호 앞은 **도구 이름**입니다. `Bash`는 명령 실행, `Edit`은 기존 파일 고치기, `Write`는 파일 새로 쓰기. 괄호 안은 **모양**이고, `*`는 "뒤에 뭐가 와도"입니다.

기억할 것이 셋 있습니다.

- **deny는 항상 이깁니다.** 어느 파일에 있든, 어떤 모드든, 허용 규칙이 따로 있어도 막힙니다. 그래서 "이 폴더는 막되 이 파일만 예외"는 못 합니다. 예외가 필요하면 막는 범위를 좁혀 씁니다.
- **모양만 봅니다.** `rm -rf /tmp/없는폴더`도 막힙니다. 대상이 안전한지는 판단하지 않습니다. 그게 의도한 동작입니다.
- **저장하면 바로 적용됩니다.** 세션을 다시 켤 필요가 없습니다. 오늘 넣고 바로 시험해서 확인했습니다.

## 어디에 적는가 — 세 층

규칙이 사는 파일이 세 개 있고, 어디에 적느냐로 적용 범위가 정해집니다.

```
~/.claude/settings.json                ← 내 PC의 모든 프로젝트 (공통)
프로젝트/.claude/settings.json          ← 이 프로젝트만. git에 올라가 저장소를 따라다님
프로젝트/.claude/settings.local.json    ← 이 프로젝트, 이 PC만. git에 안 올라감
```

첫 블로그 때는 33개가 전부 **그 프로젝트 안에만** 있었습니다. 그래서 이 블로그를 만들 때는 규칙이 하나도 없었습니다. `rm -rf`를 막는 규칙이 프로젝트마다 복사해야 하는 것이라면 뭔가 잘못 놓인 겁니다.

나누는 기준은 한 문장입니다.

> 다음 프로젝트를 만들 때 복사하고 싶어질 규칙이면 **공통**, 이 프로젝트라서 생긴 규칙이면 **프로젝트**.

## 공통에 둔 것 — 내 원칙

33개를 뜯어 보니 이 묶음들은 어느 프로젝트에서도 같아야 했습니다.

**폴더째 삭제 (7개)** — `rm -rf`와 그 변형 4개, 그리고 Windows의 `rmdir /s`, `rd /s`, `Remove-Item -Recurse` 3개. 휴지통을 거치지 않아 되돌릴 수 없습니다. 처음엔 리눅스 명령 4개만 있었는데, 이 PC는 Windows라 같은 일을 하는 문이 하나 더 열려 있었습니다. 파일 하나 지우는 `rm 파일명`은 막지 않습니다.

Windows 쪽 3개를 넣고 시험하다가 하나 배웠습니다. `Remove-Item …`으로 시작하는 규칙을 넣었는데 `powershell -Command "Remove-Item …"`처럼 **감싸서 실행하니 통과**했습니다. 규칙이 명령의 **앞부분**만 보기 때문입니다. 앞에도 `*`를 붙여 `*Remove-Item *-Recurse*`로 바꾸니 잡혔습니다. 규칙은 넣는 것보다 시험이 중요하다는 걸 또 확인한 셈입니다.

**git 기록 덮어쓰기 (6개)** — `push --force`, `push -f`, `push --force-with-lease`, `reset --hard`, `filter-branch`, `push --mirror`. git의 가치는 "되돌릴 수 있다"인데 이것들은 그 기록 자체를 지웁니다. 루틴이 먼저 푸시해 둔 글을 제가 force push로 덮으면 사라집니다. 되돌려야 하면 `git revert`나 `git stash`가 있습니다.

**관리자 권한 (1개)** — `sudo`. 이게 되면 나머지 규칙을 전부 우회할 수 있습니다.

**파일 권한 활짝 열기 (3개)** — `chmod 777` 계열. 권한 문제를 "문 다 열기"로 대충 푸는 명령입니다.

**인터넷에서 받아서 바로 실행 (8개)** — `curl … | sh`, `wget … | bash`, PowerShell의 `iwr … | iex` 같은 것. 설치 안내에 흔히 나오는 한 줄이지만 **읽어 보지도 않고 실행**하는 것입니다. 필요하면 먼저 파일로 받아 내용을 본 뒤 실행합니다.

**옵시디언 볼트 (2개)** — 볼트 안의 파일을 고치거나 만들지 않습니다. 개인 노트라 클로드가 손댈 이유가 없습니다. 읽기는 됩니다.

합쳐서 **27개**가 `~/.claude/settings.json`으로 갔습니다.

## 프로젝트에 둔 것 — 이 블로그의 약속

**패키지 설치 (7개)** — `npm install`, `npm i`, `npm ci`, `npm add`, `yarn add`, `pnpm add`, `bun add`. 이 블로그는 **의존성 0개**가 규칙입니다. `CLAUDE.md`에 적혀 있지만 그건 클로드가 읽고 지키는 약속이고, 이 규칙은 기계가 막는 겁니다. 자동 모드에서 "marked 라이브러리 쓰면 편한데"라고 판단해도 실행이 안 됩니다. 다음에 React 프로젝트를 하면 설치가 당연히 필요하니 공통에 두면 안 됩니다.

**의존성 파일 (1개)** — `Write(package.json)`. 설치는 못 해도 이 파일이 생기는 순간 "의존성 있는 프로젝트"가 됩니다. 입구를 막습니다.

합쳐서 **8개**가 `asdf-blog/.claude/settings.json`에 있고, 저장소에 올라갑니다. 첫 블로그에 있던 `dist/` 수정 금지 2개는 그쪽에만 빌드 산출물 폴더가 있어서 옮기지 않았습니다.

## 차단 규칙 말고 한 겹 더 — 샌드박스

차단 규칙과 별도로 **샌드박스**라는 장치가 있습니다. 프로젝트 폴더 밖에는 쓰지 못하게 막는 울타리입니다. 차단 규칙이 "이 명령은 안 돼"라면, 샌드박스는 "이 울타리 밖은 안 돼"입니다. 둘은 다른 층이고, 둘 다 통과해야 실행됩니다.

```
차단 규칙   →  명령·파일의 모양을 본다.  "rm -rf 는 안 돼"
샌드박스    →  경로가 울타리 안인지 본다.  "프로젝트 밖은 안 돼"
분류기     →  위험해 보이는지 판단한다.  "권한을 스스로 넓히려는 건 멈춰"
```

## 넣은 뒤에 확인하기

규칙은 넣는 것보다 걸리는지 보는 게 중요합니다. 오늘 네 가지로 확인했습니다.

- `rm -rf /tmp/없는폴더` — 없는 폴더라 실행돼도 무해 → **차단**
- `npm install lodash --dry-run` — `--dry-run`이라 설치 안 됨 → **차단**
- `git push --force origin main` — 로컬과 원격이 같은 커밋 → **차단**
- 볼트 폴더에 새 파일 쓰기 — Bash가 아닌 파일 도구로 시도 → **차단**. deny가 명령뿐 아니라 파일 도구에도 적용된다는 확인이었습니다

전부 **실패해도 아무 일이 없는** 명령입니다. 방어 장치를 진짜 위험한 명령으로 시험하면, 안 걸렸을 때 진짜로 망가집니다.

## 실수 하나

시험 중에 제가 사고를 하나 냈습니다. 쓰기가 되는지 확인하려고 **진짜 파일**을 읽고 다시 쓰는 왕복을 돌렸는데, 스크립트 한 줄의 순서 실수로 파일이 비어 버렸습니다. 다른 곳에 사본이 있어서 원본과 같은 바이트 수로 복구했지만, 없었다면 사라진 겁니다.

배운 건 코드 실수보다 앞의 것입니다.

> 시험은 임시 파일로 한다. 진짜 파일을 시험 대상으로 삼지 않는다.

이것도 `CLAUDE.md`에 적었습니다. 차단 규칙이 아무리 촘촘해도, 허용된 폴더 안에서 허용된 도구로 한 실수는 막지 못합니다. 그건 규칙이 아니라 습관의 영역입니다.

## 관리하는 법

규칙 35개를 외울 수는 없으니, 저장소에 `.claude/permissions.md`라는 문서를 두었습니다. 공통과 프로젝트로 나눠 번호를 붙이고, 줄마다 뜻과 이유를 적었습니다. 규칙을 넣고 빼면 그 문서도 같이 고칩니다. 공통 설정 파일은 git 밖에 있어서, PC를 바꾸면 이 문서를 보고 다시 만드는 용도이기도 합니다.

## 오늘의 한 줄 정리

- 차단 규칙 = 모드와 상관없이 막는 선. deny는 항상 이기고, 모양만 보고, 저장하면 바로 적용된다.
- 어디에 적느냐가 범위다. 복사하고 싶어질 규칙은 공통, 이 프로젝트라서 생긴 규칙은 프로젝트.
- 공통 27개 (삭제·git 기록·sudo·chmod·받아서 실행·볼트), 프로젝트 8개 (패키지 설치·package.json).
- 차단 규칙 위에 샌드박스와 분류기가 따로 있다. 셋 다 통과해야 실행된다.
- 넣었으면 실패해도 안전한 명령으로 확인한다. 시험은 임시 파일로.
