Daystudy #9 이후로 이 블로그에 웹앱 두 개(스도쿠, 포모도로)가 생기고, 카테고리 구조가 Daystudy·Essay·웹앱 세 갈래로 다시 짜였습니다. 그리고 그 사이에 블로그 본체(`js/app.js`, `js/markdown.js`, `js/theme.js`)가 처음으로 코드 리뷰를 받았습니다. 지금까지 리뷰는 웹앱에만 있었는데, 글을 HTML로 바꿔 화면에 꽂아 넣는 본체는 이번이 처음이었습니다. 지적 10건 중 가장 재미있었던 하나, **화면이 주소를 못 따라가는 문제**를 오늘의 주제로 잡았습니다.

## 먼저 보낸 요청이 나중에 끝날 수 있다

이 블로그는 `#/post/daystudy-9` 같은 해시로 화면을 바꿉니다. 해시가 바뀌면 `route()` 함수가 돌아서 `content/posts.json`을 불러오고, 글 파일을 `fetch`하고, 그 결과로 화면을 그립니다. 이 전부가 비동기입니다.

문제는 이렇습니다. A 글을 눌렀다가 바로 B 글을 눌렀다고 해봅시다. A 요청이 먼저 시작됐지만, B 글 파일이 더 작거나 네트워크가 먼저 풀려서 **B가 먼저 끝날 수 있습니다.** 그러면 화면엔 B가 뜹니다. 그런데 뒤늦게 A 요청도 끝나면, 그 결과로 화면을 또 덮어씁니다. 주소창은 B인데 화면은 A인 상태가 되는 겁니다.

카페에서 아메리카노와 라떼를 연달아 주문했는데, 라떼가 먼저 나와서 받아 갔더니 한참 뒤에 점원이 "아메리카노 나왔습니다"라며 그걸 내 자리에 놓고 가는 것과 같습니다. 주문은 순서대로였지만 완성은 순서대로가 아니었던 겁니다.

## 세대 번호로 늦게 온 주문을 거른다

고친 방식은 각 라우팅 호출에 번호(세대)를 매기고, 화면을 실제로 바꾸는 자리마다 "내가 아직 최신 번호인가"를 확인하는 것입니다.

```javascript
let routeVersion = 0;
const stale = version => version !== routeVersion;

async function route() {
  const version = ++routeVersion;
  // ... 해시를 해석하고 renderPost(slug, version) 같은 함수에 번호를 들려 보낸다
}
```

그리고 fetch 결과를 받아 실제로 DOM을 건드리는 지점마다 이렇게 확인합니다.

```javascript
function show(node, title, version) {
  if (stale(version)) return; // 그 사이 더 최신 호출이 있었다면 아무것도 안 한다
  app.replaceChildren(node);
  document.title = title ? `${title} — ${SITE_TITLE}` : SITE_TITLE;
}
```

B를 누르는 순간 `routeVersion`이 2로 올라갑니다. A 요청이 들고 있는 `version`은 1이라 뒤늦게 돌아와도 `stale(1)`이 `true`가 되어 그대로 버려집니다. 중요한 건 fetch를 취소하는 게 아니라 **결과를 쓸 때 한 번 더 확인한다**는 점입니다. `AbortController`로 요청 자체를 끊는 방법도 있지만, 이 블로그에는 "느려도 끝까지 받되 화면만 안 덮으면 된다"는 더 단순한 조건이면 충분했습니다.

## 재현하고 확인한 방법

커밋 기록에 따르면, 느린 적재 중에 해시를 빠르게 바꿔가며 재현했고, 고치고 난 뒤 주소와 화면이 항상 일치하는지, `posts.json` 요청이 중복으로 안 뜨는지 확인했습니다. 회귀 검사로는 홈 12개·Daystudy 9개·웹앱 2개 화면을 다시 돌았고, 375px 너비에서 가로 스크롤이 없는지와 콘솔 오류가 없는지도 봤습니다.

## 확인이 필요한 부분

- 느린 네트워크를 브라우저 개발자 도구로 직접 흉내 내 재현했는지, 코드만 보고 고쳤는지는 커밋 메시지로는 구분이 안 됩니다.
- `AbortController`를 안 쓴 이유가 "더 단순해서" 외에 다른 이유(예: 캐시 재사용 로직과의 충돌)가 있었는지 확인이 필요합니다.
- `apps/` 안의 두 웹앱(스도쿠, 포모도로)에도 비슷한 라우팅이나 비동기 로딩이 있다면 같은 문제가 있는지는 이번 리뷰 범위 밖이라 따로 봐야 합니다.

## 오늘의 한 줄 정리

- 해시가 바뀌는 속도와 fetch가 끝나는 속도는 다르다 — 먼저 보낸 요청이 나중에 끝날 수 있다.
- 세대 번호(`routeVersion`) 하나면 "지금 화면"과 "그때 요청한 화면"을 구별할 수 있다.
- 요청을 끊는 대신, 화면을 바꾸기 직전마다 "나 아직 최신이야?"만 확인하면 된다.
- 블로그 본체도 웹앱과 똑같이 리뷰 대상이다 — 지금까지는 웹앱만 검증받고 있었다.
