웹앱(포모도로·스도쿠)을 메인 화면의 상시 카드에서 떼어 「웹앱」이라는 카테고리로 옮겼습니다. 그러면서 `content/apps.json`이라는 파일을 새로 만들었는데, 처음엔 "그냥 `apps/` 폴더 안을 보면 되지 않나?" 싶었습니다. 안 되는 이유를 따라가 보니, 이 블로그가 글 목록에서 이미 풀어 둔 문제와 똑같았습니다.

## 브라우저는 폴더 안을 못 본다

서버에 파일을 올려 두고 브라우저에서 `fetch`로 가져오는 건 됩니다. 하지만 "이 폴더 안에 뭐가 있는지 보여 줘"는 안 됩니다.

```js
fetch('./apps/') // 파일 하나를 요청하는 게 아니라 폴더 목록을 요청 — 정적 호스팅엔 그런 API가 없다
```

`ls apps/`는 내 터미널에서 파일 시스템에 직접 묻는 명령입니다. 브라우저의 `fetch`는 그럴 권한이 없고, GitHub Pages 같은 정적 호스팅은 애초에 "폴더 목록을 알려주는 기능" 자체를 제공하지 않습니다. `apps/pomodoro/index.html`이라는 정확한 경로를 알아야만 그 파일을 받아올 수 있습니다.

이건 글 목록에서 이미 겪은 문제입니다. `content/posts/daystudy-9.md`를 새로 만들어도 폴더 안을 못 읽으니, `content/posts.json`에 항목을 넣기 전까지는 이 블로그 입장에서 그 글은 없는 것과 같습니다. CLAUDE.md에 "목록에 없으면 존재하지 않는 글이다"라고 적어 둔 게 바로 이 사정입니다.

## apps.json이 목록의 진실이 된다

그래서 웹앱도 같은 방식을 그대로 가져다 썼습니다. `js/app.js`에서 글 목록을 읽던 `loadIndex` 옆에 `loadApps`를 나란히 추가했습니다.

```js
const APPS_URL = './content/apps.json';
let appsCache = null;

async function loadApps() {
  if (appsCache) return appsCache;
  const res = await fetch(APPS_URL);
  if (!res.ok) throw new Error(`apps.json 을 불러오지 못했어요 (${res.status})`);
  appsCache = await res.json();
  return appsCache;
}
```

`apps.json` 자체는 그냥 배열입니다.

```json
[
  { "slug": "pomodoro", "title": "포모도로 타이머", "date": "2026-09-22", "summary": "..." },
  { "slug": "sudoku", "title": "미니 스도쿠", "date": "2026-09-21", "summary": "..." }
]
```

여기 적힌 순서가 곧 목록에 보이는 순서입니다. `apps/` 폴더에 세 번째 앱 폴더를 만들어도 이 배열에 한 줄을 추가하지 않으면 「웹앱」 카테고리에는 나타나지 않습니다. 폴더는 실제로 존재하는 파일이고, `apps.json`은 그중 "블로그에 공개하기로 한 것"의 목록입니다. 둘은 같은 게 아닙니다.

## 카테고리 하나를 값으로만 추가하기

목록을 파일로 뽑아 둔 덕분에 「웹앱」이라는 새 카테고리를 추가하는 일도 로직을 새로 안 짜고 값 하나를 더하는 걸로 끝났습니다. 카테고리 이름과 순서를 정하는 곳은 원래 이거였습니다.

```js
const CATEGORIES = { daystudy: 'Daystudy', essay: 'Essay' };
```

여기에 `apps: '웹앱'`을 추가하고, 카테고리 바의 개수를 세는 함수에 한 줄을 더했습니다.

```js
const CATEGORIES = { daystudy: 'Daystudy', essay: 'Essay', apps: '웹앱' };
// ...
counts.set(APPS, apps.length); // 글이 아니라 apps.json 의 길이를 그대로 개수로 쓴다
```

카테고리 바를 그리는 `fillCats`나 라우팅 코드는 손대지 않았습니다. "카테고리 이름 → 표시 이름"을 객체 하나에 몰아 둔 덕분에, 새 카테고리가 생겨도 그 객체에 값만 추가하면 나머지 코드는 그 값을 그대로 읽어서 처리합니다. 반대로 만약 카테고리 이름이 여기저기 문자열로 흩어져 있었다면, `apps`를 추가할 때마다 그 문자열이 쓰인 곳을 전부 찾아다녀야 했을 것입니다.

## 오늘의 한 줄 정리

- 브라우저의 `fetch`는 정확한 경로의 파일만 받아올 수 있고, 폴더 안을 목록으로 보여주는 기능은 정적 호스팅에 없다.
- 그래서 "무엇이 공개되어 있는지"는 폴더가 아니라 별도의 목록 파일(`posts.json`, `apps.json`)이 결정한다. 폴더에 파일이 있어도 목록에 없으면 블로그 입장에선 없는 것과 같다.
- 이름과 순서 같은 설정을 코드 곳곳에 흩어 두지 않고 객체 하나(`CATEGORIES`)로 모아 두면, 새 카테고리는 로직을 고치지 않고 값만 추가해서 늘릴 수 있다.

## 확인이 필요한 부분

- `apps.json`에 항목을 추가하는 순서 규칙("최신이 위")을 지금은 사람이 직접 지키고 있는데, 앱이 늘어나면 날짜 기준 자동 정렬이 필요할지 사람이 판단해야 합니다.
- 이 글에서 다룬 `apps.json` 도입과 카테고리 두 층 구조(Daystudy/Essay) 재편, `#/cat/apps` 라우팅, 사이드바를 헤더 위로 올린 레이아웃 변경은 모두 9월 22일 하루에 걸쳐 있었던 여러 커밋인데, 이 글은 그중 "목록 파일" 한 갈래만 짚었습니다. 나머지(레이아웃 변경, 팔레트·사용법 규칙)는 다른 Daystudy 편에서 다룰지 사람이 정해야 합니다.
