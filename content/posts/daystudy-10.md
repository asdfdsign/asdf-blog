블로그 글을 HTML로 바꿔 보여 주는 `js/markdown.js`를 코덱스에게 리뷰받았습니다. 치명적인 문제는 없었지만, 조용히 결과를 망가뜨리는 버그 하나를 찾아 고쳤습니다. 오늘은 그 버그 하나에만 집중합니다.

## 정규식은 글의 구조를 모른다

이 파서는 마크다운 문법 하나당 정규식 하나로 변환합니다. 코드 → 이미지 → 링크 → 강조(굵게·기울임) 순서로 돌립니다. 문제는 강조를 처리하는 정규식이, 그 앞에서 이미 `<a href="...">`로 완성된 문자열 안쪽까지 그냥 훑는다는 것입니다. 정규식은 "이건 이미 만들어진 태그니까 건드리지 마"를 모릅니다. 눈에 보이는 문자열일 뿐입니다.

예를 들어 이런 링크가 있다고 합시다.

```
[배포 노트](https://example.com/*release*)
```

링크를 먼저 만들면 이렇게 됩니다.

```html
<a href="https://example.com/*release*">배포 노트</a>
```

그다음 강조 정규식이 돌면서 `*release*`를 `<em>release</em>`로 바꿔 버립니다.

```html
<a href="https://example.com/<em>release</em>">배포 노트</a>
```

href 속성 안에 멀쩡한 HTML 태그가 끼어들어 링크 주소 자체가 깨집니다. 큰따옴표는 이미 이스케이프돼 있어서 보안 문제(XSS)는 아니지만, 아무 경고도 없이 조용히 틀린 주소로 바뀝니다. 지금까지 쓴 글에는 URL에 `*`가 들어간 적이 없어서 드러나지 않았을 뿐입니다.

## 자리표시자로 치워 두기

고친 방법은 "완성된 조각은 다음 단계가 못 보게 아예 빼 둔다"입니다. 링크·이미지·인라인 코드를 만들자마자 배열에 저장하고, 그 자리에는 NUL 문자로 감싼 번호만 남깁니다.

```js
const parts = [];
const hold = (html) => {
  parts.push(html);
  return `\u0000${parts.length - 1}\u0000`;
};

s = s.replace(/`([^`\n]+)`/g, (_, code) => hold(`<code>${escapeHtml(code)}</code>`));
// ... 이미지, 링크도 같은 방식으로 hold() 처리
```

강조 정규식이 돌 때 문자열에는 완성된 `<a href="...">` 대신 `\u00003\u0000` 같은 숫자만 남아 있습니다. `*`나 `_`로 보일 게 없으니 건드릴 수가 없습니다. 모든 변환이 끝난 뒤에야 번호를 다시 원래 HTML로 되돌립니다. 소포를 포장해서 컨베이어 벨트에 올리는 것과 비슷합니다 — 벨트에 달린 도장이 지나가는 모든 것에 찍히더라도, 포장 안쪽까지는 못 찍습니다.

한 가지 더: 링크 라벨 안에도 강조나 인라인 코드가 들어갈 수 있어서(`[**굵게**인 링크](...)`) 복원은 한 번이 아니라 자리표시자가 남지 않을 때까지 몇 차례 반복합니다. 다만 무한히 돌지는 않게 반복 횟수에 상한을 뒀습니다.

## 오늘의 한 줄 정리

- 정규식은 문자열의 뜻을 모른다. "이미 완성된 HTML이니 건드리면 안 된다"는 판단은 코드가 직접 순서를 정해 줘야 한다.
- 완성된 결과를 다음 단계로부터 숨기려면, 그 자리를 알아보기 쉬운 자리표시자로 바꿔 두고 끝에 되돌리는 방법이 있다.
- 지금까지 안 드러났다고 버그가 없는 게 아니다. 입력을 바꿔 보며 재현해야 보인다.

## 확인이 필요한 부분

- 자리표시자 복원 루프의 반복 상한(5회)이 실제로 더 깊이 중첩된 입력(예: 코드 안에 링크, 그 링크 라벨에 다시 강조)에서도 충분한지는 커밋만으로 확인할 수 없습니다. 직접 극단적인 입력으로 시험해 봐야 합니다.
- 이번에 같은 커밋에서 함께 고친 라우팅 경쟁 조건(세대 번호)이나 테마 값 검증 등 나머지 9건은 이 글에서 다루지 않았습니다. 필요하면 별도로 정리합니다.
