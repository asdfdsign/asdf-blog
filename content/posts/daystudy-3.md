"매일 저녁 그날 배운 걸 블로그에 자동으로 올려 줘." 이 한 문장을 실현하는 데 두 프로젝트에 걸쳐 여러 번 막혔습니다. 첫 블로그(my-blog)에서 하루를 통째로 썼고, 이번 블로그에서도 같은 자리에서 한 번 더 걸렸습니다. 이 글은 그 기록입니다 — 다음에 또 막혔을 때 여기부터 읽으면 됩니다.

## 스케줄러는 어디서 도는가

가장 먼저 헷갈린 것입니다. "매일 6시에 실행"이라고 하면 무언가가 6시에 깨어나야 하는데, **그게 어디에 있느냐**에 따라 할 수 있는 일이 완전히 다릅니다.

- **내 PC의 예약 작업** (Windows 작업 스케줄러) — 내 폴더를 직접 봅니다. 대신 PC가 꺼져 있으면 안 돕니다.
- **클라우드 루틴** (`/schedule`로 만드는 것) — Anthropic 서버에서 매번 새 컴퓨터를 빌려 시작합니다. PC가 꺼져 있어도 돕니다. 대신 **내 PC를 전혀 못 봅니다.**

첫 블로그에서는 처음에 Windows 예약 작업을 만들었습니다. 그런데 claude.ai의 루틴 페이지를 열어 보니 비어 있었습니다. 로컬 작업은 클라우드가 **존재 자체를 모르기** 때문입니다. 알려 준 사람이 없으니까요.

> 같은 "클로드 코드"인데, 도는 장소가 다르면 볼 수 있는 것도 다르다.

그래서 클라우드 루틴으로 가려면 재료가 클라우드가 닿을 수 있는 곳, 즉 **GitHub 저장소**에 있어야 합니다. 이번 블로그가 git 저장소가 아니었던 게 첫 번째 벽이었던 이유입니다.

## 권한은 세 겹이다

저장소를 GitHub에 올리고 나서도 막혔습니다. 오류가 나올 때마다 이유가 달랐고, 그걸 정리하니 세 겹이었습니다.

### 1겹 — 물리적으로 닿는가

저장소가 GitHub에 없으면 아무것도 안 됩니다. `git init` → `gh repo create --push`로 해결. 이건 권한이 아니라 존재의 문제입니다.

### 2겹 — 계정이 연결됐는가

첫 블로그에서 루틴을 만들려니 이런 오류가 났습니다.

```
HTTP 401
Connect your GitHub account before saving a routine that uses a GitHub repository.
```

클로드 계정과 GitHub 계정이 아직 연결되지 않은 상태였습니다. claude.ai/code 웹 화면에서 **`+ 레포 선택...`** 을 누르면 연결 안내가 뜹니다. 이건 OAuth 로그인이라 클로드가 대신 못 하고 사람이 눌러야 합니다.

여기서 한 번 헤맸습니다. 안내 링크를 클릭하니 **데스크톱 앱이 링크를 가로채서** 빈 창만 떴습니다. 크롬 주소창에 직접 붙여넣어야 했습니다. 그리고 `+ 레포 선택...` 버튼은 데스크톱 앱에는 없고 **웹(claude.ai/code)에만** 있습니다. 앱은 내 PC에서 도는 세션이라 저장소를 고를 일이 없기 때문입니다.

### 3겹 — 그 저장소에 쓸 수 있는가

계정을 연결하니 루틴이 만들어졌고, 실행도 됐습니다. 저장소를 클론하고, 글을 쓰고, 테스트까지 통과했습니다. 그런데 마지막 `git push`에서 막혔습니다.

```
HTTP 403
Resource not accessible by integration
```

이게 가장 오래 걸린 지점입니다. 원인은 GitHub 앱에 **승인(Authorize)과 설치(Install)가 따로 있다**는 것이었습니다.

- **Authorize** — "이 앱이 내가 누구인지 알아도 된다." 계정 단위. `settings/applications`에서 관리.
- **Install** — "이 앱이 이 저장소를 만져도 된다." **저장소 단위.** `github.com/apps/claude`에서 설치.

승인만 돼 있고 설치는 안 된 상태였습니다. 오류 메시지가 사실 정확했습니다 — "앱은 있는데(integration), 그 리소스에는 접근 권한이 없다."

문제를 더 늦게 알아챈 이유가 하나 더 있습니다. **공개 저장소는 권한 없이도 클론이 됩니다.** 그래서 읽기는 되고 커밋까지 만들어지는데 푸시만 안 됩니다. 읽기가 된다고 쓰기가 된다는 뜻이 아닙니다.

해결은 이 주소에서 저장소를 골라 Install하는 것이었습니다.

```
https://github.com/apps/claude/installations/new
→ Only select repositories → 저장소 체크 → Install
```

## 이번 블로그에서 다시 막힌 자리

같은 3겹 중 어디였을까요. 이번엔 루틴을 **만드는 단계**에서 403이 났습니다.

```
HTTP 403
You don't have access to a repository this routine uses.
```

이번 저장소는 처음에 **비공개**로 만들었고, 첫 블로그 때 Claude 앱을 "선택한 저장소만"으로 설치했기 때문에 새 저장소는 목록에 없었습니다. 비공개라 클론 권한조차 없으니 만들기부터 거부된 것입니다.

저장소를 **공개로 바꾸자 루틴 생성은 바로 통과**했습니다. 공개 저장소는 1겹(닿는가)과 읽기 쪽 3겹이 자동으로 풀리기 때문입니다. 저는 처음에 "공개로 바꿔도 안 될 것"이라고 예상했는데 틀렸습니다 — 생성 단계의 검사는 읽기 권한만 보고 있었습니다.

다만 **쓰기(푸시·PR)는 별개**라 앱을 이 저장소에도 설치해야 합니다. 첫 블로그와 정확히 같은 자리입니다.

## 루틴을 만들 때 같이 배운 것

- **모르는 커넥터가 자동으로 붙는다.** 루틴을 만들면 Gmail, Drive, Calendar, Notion 같은 연결이 딸려 왔습니다. 저장소만 만지면 되는 무인 에이전트에 메일 권한이 열려 있을 이유가 없어서 전부 뗐습니다. 두 번 다 그랬으니 앞으로도 만들자마자 확인해야 합니다.
- **조용히 끝내게 두지 않는다.** 첫 루틴은 커밋이 없는 날 아무 알림 없이 끝났고, 저는 그날 아무 신호도 못 받았습니다. 지금은 세 경우(썼다 / 글감이 없다 / 이미 있다) 모두 알림을 보내게 했습니다.
- **재료는 커밋뿐이다.** 클라우드 에이전트는 우리 대화를 못 봅니다. 커밋 메시지에 "왜"를 안 적으면 아무것도 쓸 수 없습니다. 대화로만 있었던 일(디자인 폐기, 권한 삽질)은 사람이 채워야 합니다. 이 글도 그래서 사람이 씁니다.
- **자동화와 사람이 같은 저장소를 쓰면 충돌한다.** 첫 블로그에서 루틴이 먼저 푸시해 놓아서 제 푸시가 거부된 적이 있습니다. 파일이 겹치지 않아 rebase로 풀렸지만, 이번엔 루틴이 main에 직접 쓰지 않고 **PR로 올리게** 해서 그 문제를 피했습니다.
- **만드는 것과 공개하는 것을 갈라놓는다.** 첫 블로그는 `draft: true`로, 이번엔 PR로. 자동화는 검토 전 단계까지만 하고 공개는 사람이 합니다.

## 다음에 막히면 볼 순서

1. 저장소가 GitHub에 있는가, 공개인가
2. 클로드 계정에 GitHub이 연결돼 있는가 — `401`이면 여기. claude.ai/code 웹에서 `+ 레포 선택...`
3. Claude 앱이 **그 저장소에 설치**돼 있는가 — 푸시에서 `403`이면 여기. `github.com/settings/installations` → Claude → Configure → 저장소 추가
4. 루틴에 불필요한 커넥터가 붙지 않았는가
5. 커밋이 없는 날도 알림이 오는가

## 오늘의 한 줄 정리

- 스케줄러가 어디서 도느냐가 먼저다. 클라우드 루틴은 내 PC를 못 본다.
- 권한은 세 겹 — 닿는가, 계정이 연결됐는가, 그 저장소에 쓸 수 있는가.
- GitHub 앱의 Authorize(계정)와 Install(저장소)은 다른 것. 공개 저장소는 읽기가 공짜라 쓰기 문제가 늦게 드러난다.
- 루틴은 만들자마자 커넥터를 떼고, 어떤 경우에도 알림을 보내게 한다.
- 자동화는 초안까지, 공개는 사람이.
