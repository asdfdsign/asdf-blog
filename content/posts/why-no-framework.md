"요즘 누가 바닐라 JS로 만드나요"라는 말을 듣습니다. 맞는 말입니다. 실무라면 저도 안 그럴 겁니다. 그런데 이건 실무가 아니라 **공부**입니다.

## 프레임워크가 감추는 것

React를 쓰면 `useState` 하나로 화면이 바뀝니다. 편리하지만, 그 밑에서 브라우저가 실제로 무엇을 하는지는 안 보입니다.

- 파일을 어떻게 가져오는지 (`fetch`)
- 문자열을 어떻게 DOM으로 바꾸는지 (`innerHTML`, `template`)
- 주소가 바뀔 때 무슨 일이 생기는지 (`hashchange`)
- 다크 모드가 왜 깜빡이는지 (첫 페인트 전에 클래스를 못 붙여서)

이런 것들은 직접 부딪혀 봐야 압니다.

## 이 프로젝트에서 직접 하는 일

### 라우팅

라우터 라이브러리 대신 해시 하나입니다.

```js
window.addEventListener('hashchange', route);

function route() {
  const hash = location.hash.slice(1) || '/';
  const post = hash.match(/^\/post\/([^/]+)$/);
  if (post) return renderPost(post[1]);
  renderList();
}
```

`#/post/hello-world` 같은 주소는 서버 설정 없이도 새로고침이 됩니다. GitHub Pages에서 404 우회 트릭을 쓸 필요가 없습니다.

### 마크다운 파서

`marked` 같은 라이브러리를 한 줄 넣으면 끝이지만, 그러면 정규식과 상태 기계를 배울 기회가 사라집니다. 대신 지원 범위를 좁게 잡고, 그 안에서 확실하게 동작하게 만듭니다.

가장 중요한 규칙 하나:

> `innerHTML`에 넣는 문자열은 반드시 이스케이프한다. 빠뜨리면 그게 XSS다.

### 다크 모드

CSS 변수 두 세트와 `data-theme` 속성 하나면 됩니다. 어려운 건 색을 바꾸는 게 아니라, **첫 화면이 깜빡이지 않게** 하는 것입니다. 테마를 정하는 스크립트를 `<head>`에서 동기로 실행해야 합니다.

## 잃는 것

솔직하게 적어 둡니다.

1. SEO — 본문이 JS로 그려지므로 크롤러에 따라 못 읽을 수 있습니다.
2. 글 목록을 `posts.json`에 손으로 관리해야 합니다.
3. 파서가 완벽하지 않습니다. 이상한 마크다운은 이상하게 나옵니다.

셋 다 알고 감수하는 겁니다. 공부용 블로그에 SEO는 필요 없고, 글이 세 자릿수가 되기 전엔 JSON 손으로 고치는 게 더 빠릅니다.

프레임워크는 나중에 언제든 얹을 수 있습니다. 밑바닥을 한 번 봐 두면, 그때 프레임워크가 무엇을 대신해 주는지 정확히 알게 됩니다.
